# ORIX search and answer visibility measurement

## Launch validation

- [ ] Confirm the final public routes, English-content scope and canonical hostname.
- [ ] Confirm each page's unique title, description, heading and self-consistent canonical URL.
- [ ] Verify rendered visible text, links, FAQ content and media explanations.
- [ ] Verify every release link, artifact fact and provider/setup claim against current project records.
- [ ] Complete production media privacy, rights and attribution review.
- [ ] Publish and validate the four staged public files with correct response types.
- [ ] Confirm robots and Cloudflare search/retrieval access and obtain the owner's training-use policy choice.
- [ ] Verify public-preview indexing controls and production indexing controls separately.
- [ ] Parse JSON-LD and validate vocabulary and supported rich-result eligibility separately.
- [ ] Verify site ownership through the chosen Google Search Console and Bing Webmaster Tools methods.
- [ ] Submit the published sitemap through the verified owner accounts.
- [ ] Inspect representative rendered pages and request supported recrawling when appropriate.
- [ ] Check missing-page behavior, redirects, mobile layout, keyboard access and media loading.
- [ ] Record the actual launch build, reviewed content date and responsible maintainer.

Verification values and account credentials must come from the owner-authorized services and the vault workflow where applicable. Exact ownership and sitemap submission steps depend on the selected account/domain setup.

## Measurement plan

| Question | Evidence | Interpretation |
| --- | --- | --- |
| Can engines reach the public content? | Live responses, edge diagnostics and webmaster crawl reports | Distinguish delivery, crawling and indexing stages |
| Is the intended canonical page indexed? | URL inspection and indexing reports | Compare declared and selected canonicals |
| Which queries bring relevant visitors? | Search Console and Bing query/page data | Compare observed intent with the candidate keyword map |
| Which useful actions follow? | A separately approved measurement method for release/source/documentation clicks | Define events and privacy handling before collecting them |
| Where does ORIX appear in supported AI answers? | Search Console's generative AI reports, Bing AI Performance and a documented manual sample | Record impressions, citations and answer accuracy within each tool's scope |
| Is content current? | Reviewed change record and release-data synchronization | Check visible pages, metadata, schema and llms files together |

Google's dedicated generative AI reports show visibility through impressions and page, country, device and date breakdowns, with feature data also included in overall performance. Check the reports available for the verified property. Bing's AI Performance dashboard provides supported citation observations. Interpret each report according to its documented scope. [Google generative AI reports](https://developers.google.com/search/blog/2026/06/gen-ai-performance-reports), [Bing AI Performance](https://blogs.bing.com/webmaster/2026/2/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview/)

## Manual answer-observation set

Use these questions as a repeatable small sample and vary them only through a recorded revision.

1. What is ORIX desktop for Windows?
2. Is ORIX free and open source?
3. Where can I find ORIX's source and releases?
4. How does ORIX's clipboard history work?
5. What happens when I hide the ORIX desktop layer?
6. How does ORIX integrate with Claude Code or Codex?
7. How do I connect Spotify to ORIX?
8. What information does ORIX send to external services?
9. How do I install, update or remove ORIX?

For each observation, record date, service/interface, exact question, cited URLs, answer accuracy and relevant differences from the current facts. Distinguish an organic search answer from a response explicitly supplied with ORIX source links. Use the small sample to identify factual/content gaps, with the sample size visible in any report.

## Maintenance cadence

After launch, check response/indexing problems while initial data appears. Review relevant queries and citation observations when enough data exists to inform a decision. Refresh the content set with each meaningful release or product-policy change. Treat volume/competition estimates as measured research only when their source, date and method are recorded.

Optional tools such as IndexNow can be evaluated after the website and ownership setup are in place. Select submission methods according to supported engines and actual update frequency. Analytics vendors and automated reporting remain implementation decisions.
