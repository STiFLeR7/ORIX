# ORIX SEO strategy

## Identity and discovery goals

Present ORIX consistently as a free, open-source desktop layer for Windows. Pair the short product name with its platform and category in titles, introductory text, social profiles and source descriptions. Use the supplied ORIX identity and the project repository as the consistent public entity references.

Primary goals are helping relevant visitors understand the product, reach the available source/release, configure supported integrations and find trustworthy usage information. Track discovery together with useful destination clicks and successful documentation journeys.

## Search intent and page ownership

| Intent | Initial owner | Content expectation |
| --- | --- | --- |
| ORIX desktop/product discovery | Home | Clear product definition, real Windows scene and feature explanation |
| Windows desktop layer/notch exploration | Home | Show the actual layer in context and describe its behavior |
| Notes, clipboard and focus tools | Relevant Home section, linked from Docs | Authentic examples with configuration and retention details |
| Claude Code/Codex monitoring and ChatGPT setup | Docs and integration section | Distinguish monitoring from provider requests and account setup |
| Installation, updates and removal | Docs | Instructions tied to the available release |
| Source, license and contribution | Home open-source section and GitHub | Accurate ISC/source/contribution links |
| Privacy and connected services | Privacy | Clear local-data and network-service information |

The [keyword map](KEYWORD-MAP.csv) assigns candidate phrases to these owners. Anchors identify sections within a page and share that page's canonical URL. Separate guide routes can be evaluated when their content is substantial and useful, with an explicit sitemap/metadata update at that time.

## On-page requirements

- Lead each page with a useful definition or task explanation and a clear primary heading.
- Use concise descriptive titles, unique descriptions and meaningful internal links.
- Keep essential product explanations, FAQ answers and release information available as HTML text.
- Support feature claims with actual captures, verified behavior and relevant documentation.
- Give images useful filenames, descriptions and surrounding explanatory copy.
- Use the canonical origin consistently and resolve duplicate route variants through the selected deployment setup.
- Keep release availability, signature status and compatibility synchronized with project records.

Titles and descriptions are editorial inputs to search presentation. Search engines may choose different displayed text. Review clarity and intent, rather than treating a character count as a ranking rule. [Google title guidance](https://developers.google.com/search/docs/appearance/title-link), [Google snippet guidance](https://developers.google.com/search/docs/appearance/snippet)

## Content quality and evidence

Use specific statements about supported tools and workflows. Link a feature's setup instructions and relevant data disclosure. Cite actual test/release records when making verification claims. Attribute update dates to substantive reviewed changes.

Use factual maintainer information approved for publication. Reviews, testimonials, download totals, performance statistics, customer logos and endorsements need genuine attributable evidence. Third-party marks identify supported integrations and retain their applicable attribution.

## Technical requirements

Serve approved pages over HTTPS with correct status codes, self-consistent canonical URLs, crawlable links and stable metadata. Include only canonical indexable pages in the sitemap. Use a real missing-page response for unknown routes. Account for redirects, query variants, page rendering, static-asset delivery and bot access at the Cloudflare edge.

The initial sitemap follows the three proposed page routes. Generate or review it against the final route inventory. Use modification dates only when they represent actual significant content changes. [Google sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)

## Scope and prioritization

First establish a correct public entity, accurate content, working links and accessible pages. Then evaluate query data, documentation demand and citation observations to decide whether additional guides are justified. Assign every new page a clear audience need and content owner.

The current handoff supplies a focused product site. Accounts, forms, analytics vendors, localization and expanded editorial publishing remain separate product decisions when requested.
