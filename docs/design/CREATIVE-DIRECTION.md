\# ORIX — Complete Creative Direction \& Product Design Specification



\*\*Product:\*\* ORIX  

\*\*Category:\*\* Windows Desktop Interaction Layer  

\*\*Design Philosophy:\*\* Native feel. Fluid interaction. Expressive identity.  

\*\*Creative Direction:\*\* Premium, futuristic, minimal, playful where appropriate, and technically sophisticated.



\---



\# 01. Product Vision



ORIX is a persistent desktop interaction layer designed to make Windows more accessible, expressive, and productive.



It introduces a compact, contextual interface that sits naturally within the desktop environment. Users should be able to access useful system functions, notifications, shortcuts, widgets, accessibility features, and contextual interactions without constantly switching between applications.



ORIX should feel less like another application and more like an extension of the operating system.



\### Core design philosophy



\- Native in behavior, premium in appearance.

\- Minimal by default, expressive when expanded.

\- Contextual rather than cluttered.

\- Functional before decorative.

\- Personalized without becoming complicated.

\- Fluid transitions and meaningful interactions.



\### Brand positioning



\*\*ORIX — Your desktop, within reach.\*\*



Alternative messaging:

\- A smarter layer for Windows.

\- Everything, one interaction away.

\- Your workspace. Reimagined.

\- Beyond the desktop.



The visual identity must communicate intelligence, accessibility, modularity, and continuous presence.



\---



\# 02. Overall Visual Language



The visual language should combine three design influences:



1\. macOS-inspired desktop refinement.

2\. Modern glassmorphism and translucent material design.

3\. Contemporary futuristic product interfaces.



The goal is not to reproduce macOS Finder or Dynamic Island. The goal is to understand why these interfaces feel premium and translate those principles into an original Windows experience.



\### Design characteristics



\- Rounded geometric surfaces.

\- Carefully controlled transparency.

\- Layered depth and subtle shadows.

\- Thin borders and soft highlights.

\- Restrained use of gradients.

\- Smooth animations.

\- High-quality typography.

\- Consistent spacing and alignment.

\- Expressive but controlled iconography.



Avoid excessive neon, unnecessary glowing borders, generic AI visual effects, and oversized gradients.



ORIX should look sophisticated even when every decorative effect is removed.



\---



\# 03. Desktop Experience — ORIX Interaction Layer



This is the most important part of the product.



The desktop interaction layer must be designed as a first-class product experience, not as a small dashboard squeezed into the screen.



\### 3.1 Default state



The default interface should remain compact and unobtrusive.



The interface should:

\- Occupy minimal screen space.

\- Remain visually integrated with the desktop.

\- Respond to user interaction.

\- Support mouse and keyboard interaction.

\- Expand into contextual content.

\- Support configurable appearance and positioning.



The compact interface should become a recognizable ORIX signature.



\### 3.2 Expanded state



When activated, the compact interface should smoothly expand into a floating contextual panel.



The expanded panel can contain:

\- System status.

\- Notifications.

\- Quick actions.

\- Media controls.

\- Accessibility shortcuts.

\- Clipboard access.

\- Calendar and time information.

\- Running application information.

\- Configurable widgets.

\- User-selected mascot interactions.



Organize information into logical groups rather than displaying everything simultaneously.



\### 3.3 Material and appearance



Use two primary visual treatments.



\*\*Dark Glass\*\*



\- Deep graphite and near-black surfaces.

\- Translucent backgrounds.

\- Soft inner highlights.

\- Subtle borders.

\- Light text with appropriate contrast.

\- Restrained reflections.



\*\*Light Glass\*\*



\- Frosted white surfaces.

\- Neutral grey typography.

\- Soft ambient shadows.

\- Subtle separators.

\- Controlled background blur.

\- Carefully balanced transparency.



Both modes must feel like two versions of the same design system.



\### 3.4 Interaction behavior



Animations must feel intentional and responsive.



Recommended interaction patterns:

\- Expand and collapse with spring-based motion.

\- Smooth opacity and scale transitions.

\- Subtle hover feedback.

\- Soft state transitions.

\- Contextual content reveal.

\- Smooth mascot reactions.

\- Reduced-motion support.



Avoid animations that delay access to functionality.

\# 04. Companion Dashboard — Main Application



The dashboard is the central configuration and personalization experience for ORIX.



Use the supplied references as inspiration for the dashboard's visual language, not as fixed layouts to reproduce.



The dashboard should feel like a premium desktop application with a carefully designed information hierarchy.



\### 4.1 Dashboard layout



Use a modular architecture with the following sections:



\*\*A. Overview\*\*



The primary landing experience.



Include:

\- ORIX branding.

\- Welcome or contextual greeting.

\- Current desktop interaction-layer status.

\- Enable/disable control.

\- Selected mascot preview.

\- Recently used features.

\- Quick access to personalization.

\- Relevant system information.



The enable/disable interaction should be visually prominent.



Consider a large, distinctive pill-shaped switch with a clear ON/OFF state.



The switch should feel tactile and satisfying, inspired by the supplied toggle reference.



\*\*B. Appearance\*\*



Allow users to personalize the visual behavior of ORIX.



Include:

\- Dark mode.

\- Light mode.

\- System-following mode.

\- Transparency intensity.

\- Blur intensity.

\- Accent color.

\- Corner radius.

\- Animation preferences.

\- Interface positioning.

\- Compact and expanded appearance settings.



Provide live previews wherever possible.



\*\*C. Mascot Studio\*\*



A dedicated space to select, preview, and personalize the ORIX mascot.



Include:

\- Mascot gallery.

\- Mascot detail previews.

\- Animation previews.

\- Default mascot selection.

\- Visibility preferences.

\- Interaction behavior.

\- Optional sound and animation settings.



\*\*D. Modules\*\*



A centralized feature management section.



Potential modules:

\- Quick Actions.

\- Notifications.

\- Media Controls.

\- Clipboard.

\- Accessibility.

\- Widgets.

\- Productivity Tools.

\- System Monitoring.



Each module should have an independent enable/disable control and configuration panel.



\*\*E. Settings\*\*



Keep system-level configuration separate from visual personalization.



Include:

\- General.

\- Startup behavior.

\- Keyboard shortcuts.

\- Permissions.

\- Display preferences.

\- Performance.

\- Accessibility.

\- Updates.

\- About ORIX.

\# 05. Dashboard Design Language



The dashboard should prioritize clarity and premium visual quality.



\### Layout principles



\- Use a consistent grid system.

\- Establish a clear hierarchy between page titles, section titles, and supporting text.

\- Avoid excessive cards.

\- Avoid unnecessary nested containers.

\- Use generous but disciplined spacing.

\- Keep related controls grouped.

\- Make important settings discoverable.

\- Use contextual descriptions instead of long paragraphs.



\### Surfaces



Use a combination of:

\- Translucent primary surfaces.

\- Solid secondary surfaces.

\- Subtle outlined containers.

\- Floating contextual panels.

\- Softly elevated interactive elements.



Do not make every component look like a glass card.



Glass should be a material choice, not a decoration applied everywhere.



\### Typography



Use a modern, highly readable sans-serif family.



Suggested directions:

\- Inter.

\- Geist.

\- Manrope.

\- Segoe UI Variable.



Typography should be consistent across the dashboard and desktop layer.



Use:

\- Strong page headings.

\- Medium-weight section headings.

\- Regular-weight descriptions.

\- Compact metadata.

\- Highly legible numerical information.



\### Color system



Primary foundation:

\- Graphite.

\- Near-black.

\- White.

\- Cool grey.

\- Neutral silver.



Accent palette:

\- Electric blue.

\- Soft cyan.

\- Muted orange.

\- Subtle lime.



Accents should indicate actions, states, and meaningful information rather than being used decoratively.



Dark and light themes must both be first-class experiences.

\# 06. ORIX Mascot Ecosystem



The mascot system is one of the most distinctive opportunities for ORIX.



The supplied mascot reference suggests expressive, character-driven icons with distinctive silhouettes, bold shapes, and colorful app-icon treatments.



Build this into a proper mascot ecosystem rather than treating mascots as ordinary decorative illustrations.



\### 6.1 Mascot design philosophy



Each mascot should:

\- Have a recognizable silhouette.

\- Be visually distinctive at small sizes.

\- Communicate a personality.

\- Support multiple expressions.

\- Work in both static and animated formats.

\- Have a consistent rendering style.

\- Remain recognizable across different backgrounds.



The mascots should feel like characters belonging to the same universe.



\### 6.2 Mascot visual style



Explore:

\- Rounded geometric silhouettes.

\- Soft 3D-inspired forms.

\- Glossy or matte finishes.

\- Subtle depth.

\- Expressive eyes.

\- Distinctive facial features.

\- Carefully controlled gradients.

\- Rich but balanced colors.



Avoid making every mascot look like a generic cartoon animal.



Create variety through shapes, expressions, personalities, and visual themes.



\### 6.3 Mascot selection experience



The mascot selection page should feel like a character gallery.



Each mascot should have:

\- A large preview.

\- Name.

\- Short personality description.

\- Animation preview.

\- Selection state.

\- Available expressions.

\- Interaction examples.



The user should be able to preview how a mascot behaves in the desktop interaction layer before selecting it.



\### 6.4 Mascot interaction states



Design a consistent animation and expression library:



\- Idle.

\- Hover.

\- Active.

\- Excited.

\- Thinking.

\- Notification.

\- Success.

\- Error.

\- Sleeping.

\- Hidden.



Do not force mascots into every interaction.



Mascots should enhance the experience without interrupting productivity.



\### 6.5 Mascot customization



Consider future support for:

\- Mascot themes.

\- Alternate expressions.

\- Animation intensity.

\- Visibility controls.

\- Optional sound effects.

\- Seasonal appearances.

\- Community-created mascot packs.



Mascots should be modular assets that can be added without redesigning the application.

\# 07. Iconography and Component Design



Use a consistent icon system throughout ORIX.



Icons should be:

\- Minimal.

\- Geometric.

\- Recognizable.

\- Consistent in stroke weight.

\- Clear at small sizes.



Prefer familiar symbols for system functions.



Use custom icons only when they provide meaningful product identity.



\### Component library



Establish reusable components for:



\- Buttons.

\- Icon buttons.

\- Toggles.

\- Sliders.

\- Dropdowns.

\- Navigation items.

\- Tooltips.

\- Context menus.

\- Notification items.

\- Widget containers.

\- Mascot cards.

\- Preview panels.

\- Settings rows.

\- Floating panels.



All components should support light and dark themes.



Define hover, focus, pressed, disabled, selected, and loading states.



\---



\# 08. Motion and Micro-interactions



Motion is a major part of the ORIX experience.



It should make the interface feel responsive, tactile, and alive.



\### Motion principles



\- Fast interaction feedback.

\- Smooth expansion and contraction.

\- Natural easing.

\- Subtle depth transitions.

\- Consistent animation durations.

\- No unnecessary bouncing.

\- No excessive parallax.

\- Reduced-motion support.



\### Important interactions to design



1\. Activating the ORIX desktop layer.

2\. Expanding the compact interface.

3\. Opening contextual widgets.

4\. Switching themes.

5\. Enabling and disabling ORIX.

6\. Changing mascots.

7\. Opening notification panels.

8\. Showing quick actions.

9\. Switching between dashboard sections.



Every interaction should have a clear visual response.



\---



\# 09. Accessibility and Usability



Accessibility is a core product capability, not a secondary feature.



The interface must support:

\- Keyboard navigation.

\- Screen-reader-friendly labels.

\- High-contrast options.

\- Adjustable interface scaling.

\- Reduced motion.

\- Clear focus indicators.

\- Configurable shortcuts.

\- Accessible control sizes.

\- Appropriate text contrast.



Do not allow transparency or blur effects to compromise readability.



Ensure all essential functionality remains available without requiring mouse interaction.

\# 10. Design Consistency and Product Architecture



ORIX has three visual surfaces, but they must share one coherent design system.



\### Surface A — Desktop Layer

Compact, contextual, responsive, and unobtrusive.



\### Surface B — Companion Dashboard

Structured, configurable, informative, and visually polished.



\### Surface C — Mascot Ecosystem

Expressive, character-driven, modular, and customizable.



All three should share:

\- Typography.

\- Color tokens.

\- Corner-radius rules.

\- Iconography.

\- Interaction patterns.

\- Motion principles.

\- Component behavior.



The desktop layer should feel like the product's live experience.



The dashboard should feel like its control center.



The mascots should feel like its personality.

ORIX should establish a recognizable identity in the Windows ecosystem.



It should combine the refinement of premium desktop software, the fluidity of modern interaction design, and the personality of an expressive mascot universe.



The experience should be:



\*\*Minimal when idle. Powerful when activated. Personal by design.\*\*



The desktop layer is the product.



The dashboard is the control center.



The mascots are the personality.



The design system is what connects everything.



\*\*ORIX — Your desktop, within reach.\*\*







My additional recommendations

There are five things I'd emphasize beyond the visual references.



1\. Design the interaction layer first



Don't spend all the effort on the dashboard. The floating interface is what users will interact with every day. Perfect its compact, expanded, and contextual states first.



2\. Make the ON/OFF switch iconic



The toggle can become one of ORIX's recognizable interaction elements. Give it tactile feedback and a distinctive transition.



3\. Treat mascots as a product feature



Give each mascot a name, personality, expression library, and animation states. Eventually support community-created mascot packs.



4\. Respect Windows native behavior



Use the visual language of acrylic and Mica where appropriate, while maintaining ORIX's own identity. Handle DPI scaling, multiple monitors, taskbar positioning, and accessibility properly.



5\. Build an actual design system



Establish tokens, components, mascot specifications, and asset conventions before scaling the interface. This prevents visual inconsistency as features grow.



My strongest strategic recommendation: Don't let ORIX become just another customization utility. Build it as a modular desktop interaction platform. The notch-like interface is its entry point, not its entire identity.
